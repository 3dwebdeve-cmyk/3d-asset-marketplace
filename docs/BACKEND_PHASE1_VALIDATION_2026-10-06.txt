Implemented behavior

1. Currency policy
- Supported currencies: USD, EUR, GBP, INR (two decimal places), and JPY
  (whole yen). Unknown currencies and invalid precision are rejected.
- Shared exact conversion is used for checkout line items, simulated confirmation,
  fulfillment amount validation, sandbox smoke helpers, and refund accounting.
- Catalog create/update and batch import enforce currency/precision rules.
- Currency floor checks reject unsupported zero-total checkout and amounts below
  USD 0.50, EUR 0.50, GBP 0.30, INR 0.50, and JPY 50.
- These floors do not certify merchant-country/settlement/payment-method support;
  Stripe remains authoritative for account-specific limits. Adding currencies
  requires deliberate precision/refund tests and account support verification.
- Zero-price catalog rows are permitted, but a whole zero-total order cannot be
  fulfilled through checkout until a separate free-order flow is implemented.

2. Password changes and resets
- Password change reloads and locks the user inside a database transaction before
  checking active/verified state and current password.
- Reset confirmation locks the current user before validating/consuming its token.
- Password mutation, token-version increment, outstanding refresh revocation,
  and the password-change notification job are committed together.
- Concurrent credential operations cannot overwrite changes using stale account
  snapshots or roll the token version backwards. Outbox failures roll back the
  password mutation; successful resets now also notify the account owner.

3. Publishing
- Products must be created as drafts before packages can be attached.
- Manual publication/PATCH and QA approval require a private package object and a
  preview pointer, plus valid category/pricing. Flags alone do not establish readiness.
- Batch approvals retain their SKU requirement; manual products need not gain a
  batch SKU. Imported products retain the dedicated approval-path restriction.
- Product mutation/approval and plugin mutation reload/lock their current rows.
- Plugin currency rules and package readiness also apply to published updates.
- Existing tests expecting ungated publishing were revised to cover rejection
  before packages/previews exist and success after supplying them.
